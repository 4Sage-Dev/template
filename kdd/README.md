# Key Design Decisions (KDD)

## How This Works

The KDD framework organizes game design decisions in a hierarchy where
higher-level answers constrain and drive lower-level questions. Not every
question needs to be pre-planned — only the key decision points at each
level. An LLM generates follow-on questions based on the answers given,
using game design knowledge to probe into the implications of each choice.

## Decision Priority

Every decision is classified by why it matters:

**Must-Have (MH)** — Non-negotiable constraints.
  - Platform requirements and hardware limits
  - Budget and team size realities
  - Existing commitments (publisher contracts, IP obligations)
  - Physics and technical impossibilities
  - These are facts to be discovered and recorded, not choices to be made.

**Should-Have (SH)** — Strongly recommended defaults.
  - Genre conventions players expect
  - Industry best practice
  - Proven patterns with known trade-offs
  - Deviation requires documented justification.

**Nice-to-Have (NH)** — Opportunistic improvements.
  - Polish and quality-of-life features
  - Additional content
  - Future flexibility
  - Trade off against scope, cost, and timeline.

**Won't-Have (WH)** — Explicitly excluded.
  - Features consciously cut from scope
  - Design directions deliberately avoided
  - Documenting what you chose *not* to do prevents scope creep.

## Design Cascade

Decisions flow from the most constrained (top) to the most flexible (bottom).
A single answer at a high level can resolve or reshape dozens of questions
below it.

```
Level 0: Vision & Constraints          ← immovable facts and creative vision
Level 1: Player Experience             ← emotional and experiential goals
Level 2: Core Design                   ← game loop, mechanics, progression
Level 3: Systems & Content Design      ← detailed systems, narrative, content
Level 4: Presentation                  ← art, audio, UI/UX, game feel
Level 5: Architecture & Technology     ← engine, networking, tools
Level 6: Implementation               ← code, testing, deployment, live ops
```

Each level's KDD file contains the key questions for that level.
Follow-on questions are generated by the LLM based on answers given.

## File Structure

```
kdd/
├── README.md                    ← this file
├── L0-vision.md                 ← game concept, genre, platform, audience, team
├── L1-experience.md             ← player experience and emotional goals
├── L2-core-design.md            ← game loop, mechanics, progression
├── L3-systems-content.md        ← detailed systems, narrative, level design
├── L4-presentation.md           ← art direction, audio, UI/UX, game feel
├── L5-architecture.md           ← engine, networking, data, tools
└── L6-implementation.md         ← code patterns, testing, deployment
```
